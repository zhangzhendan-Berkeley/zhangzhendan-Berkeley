CS180: Intro to Computer Vision and Computational Photography

Author: Zhang Zhendan

Overview

In this project, I implement a full Neural Radiance Field (NeRF) system from scratch. This includes camera calibration, pose estimation, multiview ray sampling, volume rendering, and training neural networks for both 2D neural fields and 3D radiance fields. The entire NeRF pipeline is built in PyTorch, following the project specification closely.

My implementation supports both the provided LEGO dataset and a custom dataset (photos of my computer mouse), with improvements such as checkpoint-based training, increased sampling resolution, and custom rendering hyperparameters for high-quality reconstruction.

Part 0 — Calibrating the Camera and Capturing a 3D Scan

For Part 0, I completed the full calibration pipeline: Aruco detection → camera intrinsic calibration → pose estimation (PnP) → undistortion → dataset packaging. These calibration results are required to produce accurate camera-to-world matrices for NeRF training.

0.1 — Camera Calibration

I captured 39 calibration images of 4×4 ArUco markers using a fixed zoom level. In each image, I detected all visible tags and collected the corner correspondences. I then used cv2.calibrateCamera() to compute the intrinsic matrix \(K\) and distortion coefficients.

Sample calibration images captured from various angles.

0.2 — Capturing Object Scan

I chose a small mouse as the object for my custom NeRF in Part 2.6. I printed a single ArUco tag with a white border and placed the mouse next to it. I then captured 80 images around the object at varying angles and heights.

Example images from my mouse dataset captured for Part 2.6.

0.3 — Camera Pose Estimation (PnP)

For each image, I detected the single printed ArUco tag and extracted its corner coordinates. Using the known tag size, I constructed the 3D points and applied cv2.solvePnP to estimate rotation and translation. Because SolvePnP returns a world-to-camera transform, I inverted it to obtain the camera-to-world (c2w) matrix required for NeRF.

Visualization of estimated camera frustums using Viser.

0.4 — Undistorting Images and Building the Dataset

Finally, I undistorted each captured image using the recovered intrinsic matrix and distortion coefficients. I then split the dataset into training, validation, and test sets, and saved everything in .npz format:

  • images_train: Undistorted training images
  • c2ws_train: Training camera-to-world matrices
  • images_val: Validation images
  • c2ws_val: Validation poses
  • c2ws_test: Test poses for novel-view synthesis
  • focal: The recovered focal length (fx=fy)

Part 1 — Fitting a Neural Field to a 2D Image

Before implementing a full NeRF, I built a 2D neural field that maps 2D pixel coordinates to RGB values. This part helps validate the positional encoding logic, MLP architecture, and optimization loop, all of which extend directly to 3D NeRF.

1.1 — Network Architecture

My model is an MLP with Sinusoidal Positional Encoding (PE). For a normalized 2D coordinate \((x,y)\in[0,1]^2\), the encoding is \[ \phi(x,y) = [\,x,y,\ \{\sin(2^k \pi x),\ \cos(2^k \pi x),\ \sin(2^k \pi y),\ \cos(2^k \pi y)\}_{k=0}^{L-1}\,], \] which gives an input feature dimension of \(2 + 4L\) (e.g., \(L=10 \Rightarrow 42\) dims). The MLP uses a hidden width of 256 and ends with a Sigmoid to output RGB in \([0,1]\). I train with Adam (lr \(=1\text{e}{-2}\)), batch size \(=10{,}000\), and \(1\text{k}\sim10\text{k}\) iterations, reporting PSNR during training.

MLP architecture used for the 2D neural field.

1.2 — Dataloader for Pixel Sampling

For each training iteration, I randomly sample 10,000 pixels from the target image. Each sample consists of:

  • Normalized coordinates: $(x/W, y/H)$
  • Normalized RGB colors: in range [0,1]

1.3 — Loss, Optimizer, and Training

I used:

  • Loss: Mean Squared Error (MSE)
  • Optimizer: Adam with learning rate 1e-2
  • Iterations: 1000–3000
  • Metric: Peak Signal-to-Noise Ratio (PSNR)

Part 2 — Neural Radiance Field from Multi-view Images

In Part 2, I extend the 2D neural field to a full 3D NeRF by predicting spatial density and view-dependent color for each sample point along camera rays. This section describes the geometric operations required before training.

2.1.1 — Camera-to-World Transform

A 3D point in camera coordinates is transformed to world coordinates by:

$$x_w = R x_c + t$$

I implemented a function supporting batch inputs and validated it using the identity:

$$x_c = c2w^{-1}(c2w(x_c))$$

2.1.2 — Pixel to Camera Coordinates

Using the intrinsic matrix

\( K = \begin{bmatrix} f & 0 & c_x \\ 0 & f & c_y \\ 0 & 0 & 1\end{bmatrix} \)

I invert the projection equation to compute camera-space coordinates of each pixel at depth 1. This enables construction of ray directions.

2.1.3 — Pixel-to-Ray Conversion

A ray is defined by:

  • Origin: camera position (c2w[:3,3])
  • Direction: normalized vector from the camera through the pixel
Ray casting visualization: sampling rays and 3D points along each ray.

2.2 — Sampling Points along Rays

For each ray, I uniformly sample n_samples = 64 points in the range [near, far]. During training I enable stratified perturbation to improve coverage.

2.4 — NeRF Network

I implemented a full NeRF-style MLP following the architecture described in the original NeRF paper. The network predicts both the density σ and the RGB color for each sampled 3D point along a ray. The implementation is located in nerf_network.py.

MLP architecture used for the 3D neural field.

Positional Encoding

Both the 3D world coordinates x ∈ ℝ³ and the 3D viewing directions d ∈ ℝ³ are encoded using sinusoidal positional encodings (PE). For each input channel, the encoding expands the vector into: 

[x, sin(2⁰πx), cos(2⁰πx), ..., sin(2⁽ᴸ⁻¹⁾πx), cos(2⁽ᴸ⁻¹⁾πx)]

The coordinate encoding uses Lx = 10 frequency bands, producing 3 × (2Lx + 1) = 63 features. The viewing-direction encoding uses Ld = 4, producing 27 features.

MLP Architecture

The NeRF MLP consists of:

  • 8 fully connected layers with width W = 256
  • Skip connection at layer 4, where the input PE is concatenated again
  • A density (σ) head: ReLU(W → 1)
  • A color (RGB) head conditioned on view direction:
    • Extract features from the coordinate tower
    • Concatenate with direction PE
    • Two-layer MLP → Sigmoid output in [0,1]

This matches the NeRF design: density depends only on the 3D position, while the RGB color depends on both the point and the viewing direction.

2.5.1 — Volume Rendering

Let a camera ray be r(t) = o + t·d with near/far bounds tn and tf. Following NeRF, the pixel color is the transmittance-weighted integral of per-point radiance:

Continuous formulation used by NeRF (transmittance × density × color).

Discrete approximation

We sample depths {ti} uniformly (or stratified with jitter) between [tn, tf], with step sizes Δi = ti+1 − ti. Denote network outputs at each sample as σi and rgbi. The standard alpha-compositing form is:

  • αi = 1 − exp(−σi · Δi) (termination prob. at sample i)
  • Ti = ∏j<i (1 − αj) (transmittance up to i)
  • wi = Ti · αi (compositing weight)
  • C(r) = Σi wi · rgbi

Depth (or opacity) can be accumulated analogously using the same weights wi. During training we use stratified sampling (noise within each bin) and during evaluation we disable jitter for deterministic renders.

Implementation notes

  • All ops are vectorized in PyTorch; we use torch.cumsum / torch.cumprod to build Ti and wi efficiently.
  • Numerical stability: clamp densities and transmittance with small eps (e.g., 1e−10).
  • Shapes: sigmas is [B, N, 1], rgbs is [B, N, 3], step size array Δ is [N] or [B, N, 1], output color is [B, 3].
  • Background color: if desired, add Tfinal · bg after the sum.

2.6 — Training NeRF with My Own Data (Mouse)

I collected a custom dataset consisting of 80 photos of a computer mouse next to a printed 4×4 ArUco tag. Using the same calibration pipeline from Part 0, I produced undistorted images and corresponding c2w poses. The scene is small and close to the camera, so I carefully tuned near/far and sampling density to avoid floating foggy voxels and to improve reconstruction.

Sample views from the mouse dataset and the capture setup with a printed ArUco tag.

2.6.1 — Engineering & Hyperparameter Choices

  • Checkpoint-first training: during training I save checkpoints but do not render intermediate images to reduce peak VRAM usage; I render after training completes.
  • Samples per ray: n_samples = 128 (↑ from 64) to improve quality on my real data.
  • Model capacity: NeRF hidden width = 512 to better fit high-frequency details.
  • Training schedule: iters = 40,000 total iterations.
  • Rays per iteration: batch_rays = 5,000 (↓ to keep VRAM manageable).
  • Near/Far range: near = 0.001, far = 1.0 to mitigate mid/far fogging and near-plane occlusion artifacts.
  • Rendering chunk: chunk = 8192 during inference; 16384 OOMs on 16 GB with width=512, so I cut it in half and pay extra time instead.
  • Optimizer: Adam, LR = 5e-4 (cosine decay to stabilize late training).

Why these choices?

A larger MLP and more samples per ray substantially improve reconstruction fidelity, but increase memory. By lowering batch_rays and deferring renders until the end, I keep peak memory within 16 GB. The tighter [near, far] also removes translucent “air” density that otherwise appears when the sampling slab is too large for a close-range desk scene.
